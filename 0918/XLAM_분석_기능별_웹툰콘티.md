
# VbaCode XLAM 분석 및 한국어 웹툰형 사용 설명서 설계

분석일: 2026-09-18. 대상: Windows 데스크톱 Excel 2024. 이 문서는 **코드에서 확인한 동작**과 **실행 확인 필요 항목**을 구분한다. 실제 Excel에서 매크로를 실행하거나 파일을 수정하지 않았다. 콘티는 그림 제작 전 단계의 컷·대사 설계다.

## 1. 분석 범위와 추출 결과

이전 대화 첨부파일의 `vbacode.xlam.zip`과 `Excel Customizations.exportedUI`를 확보했다. ZIP 안에는 `vbacode.xlam` 하나가 있다. XLAM 패키지의 `xl/vbaProject.bin`에서 OLE 스트림을 읽고 압축 VBA 소스를 복원했다. 한글은 CP949로 해석했다. 배포용 소스는 줄 간 빈 줄만 정리한 읽기용 사본이며 원본은 수정하지 않았다. 컴파일된 P-code와 소스의 일치 검증, VBA 컴파일, 외부 참조 라이브러리 정상 여부, 폼 화면 렌더링은 확인 필요다.

결과: 표준 모듈 8개, 문서 모듈 2개, UserForm 1개, 총 코드 모듈 11개·프로시저 32개. 문서 모듈 `현재_통합_문서`, `Sheet1`에는 실행 프로시저가 없다. 시트 XML은 빈 Sheet1 하나이며, 내부 customUI, 워크시트 버튼/그림/VML 연결은 발견되지 않았다. VBA 서명 파트도 패키지에서 발견되지 않았다(인증서 신뢰 검증은 별도).

리본은 XLAM 내장이 아니라 별도 exportedUI에 들어 있다. `CustomFunction` 탭의 그룹은 Delete, Merge, Korean, Calc, Fill, Find, Report, About이며 버튼 22개가 전부 `C:\excel\vbacode.xlam!프로시저`에 연결된다. 연결 대상 22개 모두 추출 코드에서 찾았다. exportedUI에는 빠른 실행 도구 모음 변경과 그리기 탭 숨김도 포함되어 있다.

## 2. 먼저 알아둘 중요한 차이

- RowDelete는 선택한 셀 주변만 지우는 것이 아니라 기준 열을 1행부터 검사하여 **행 전체**를 지운다.
- RestoreBackup은 시트 전체를 지운 뒤 **값만** 복원한다. 수식·서식 복구나 일반 실행 취소가 아니다.
- 단어조사연결은 단어와 조사 합친 문장이 아니라 **조사만** 반환한다.
- 바이트 길이는 한글 음절 3/그 외 코드 단위 1 규칙이다. 제출 시스템의 공식 바이트 규칙과 동일하다는 검증은 없다.
- 오답표시는 **허용 정답 목록 포함 여부**를 표시하려는 구현이다. 위치별 정답 비교가 아니며 유효성 검사 설정 실패를 숨길 수 있다.
- 해제하기는 원래 채우기 색과 조건부 서식도 지운다. 매크로로 변경한 작업의 Ctrl+Z 복구를 보장하지 않는다.

## 3. Excel 2024 설치와 안전한 보안 안내

### 3-1. 현재 파일 그대로 쓰는 설치 순서

1. 작성자·배포 경로와 버전을 확인하고, Excel을 종료한다. ZIP은 압축을 풀고 XLAM 실제 파일을 확인한다.
2. 기존 exportedUI를 그대로 쓸 경우 `C:\excel\vbacode.xlam`에 저장한다. 다른 위치를 사용하려면 작성자가 리본 연결을 다시 만들거나 사용자가 해당 위치의 매크로를 새 그룹에 등록해야 한다. 단순히 XLAM을 등록해도 기존 절대경로 버튼은 자동으로 맞춰지지 않는다.
3. 인터넷 차단과 조직 정책을 아래 구분에 따라 확인한다. 출처 검증 전에는 차단 해제·신뢰 설정을 하지 않는다.
4. Excel에서 **파일 → 옵션 → 추가 기능 → 아래 관리: Excel 추가 기능 → 이동 → 찾아보기 → vbacode.xlam 선택 → 목록에서 체크 → 확인**. COM 추가 기능이나 온라인 Office 추가기능 등록 메뉴와 구분한다. [Microsoft: 추가기능 등록](https://support.microsoft.com/en-us/excel/add-or-remove-add-ins-in-excel)
5. 버튼을 만들려면 **파일 → 옵션 → 리본 사용자 지정**에서 현재 설정을 가져오기/내보내기의 ‘모든 사용자 지정 내보내기’로 먼저 보관한다. 이후 ‘사용자 지정 파일 가져오기’에서 첨부 exportedUI를 선택한다. 기존 리본·빠른 실행 도구 모음 설정이 대체될 수 있다. 가져온 CustomFunction 탭이 체크되어 있는지 확인한다. [Microsoft: 리본 사용자 지정](https://support.microsoft.com/en-us/office/foundations-experiences/customize-the-ribbon-in-office)
6. 기존 UI를 유지하고 싶다면 새 탭·새 그룹을 만들고 명령 선택에서 ‘매크로’를 골라 실제 XLAM의 공개 Sub를 등록한다. 목록에 보이지 않으면 작성자에게 연결 지원을 요청한다. 필요하면 Excel 재시작 후 ‘정보’로 연결을 확인하고 복사본에서 기능을 시험한다.

### 3-2. 인터넷에서 받은 파일 차단

Windows가 인터넷 출처 표시(Mark of the Web)를 붙인 XLAM은 추가기능으로 등록해도 실행이 막힐 수 있다. 검증된 파일이라면 **압축 해제한 XLAM → 우클릭 → 속성 → 일반 → 차단 해제(표시되는 경우) → 적용/확인**으로 해당 파일의 출처 표시를 제거한다. ZIP 차단을 먼저 해제하고 다시 풀 수도 있지만, 추출된 XLAM의 속성을 다시 확인한다. ‘차단 해제’가 안 보인다고 모든 보안 원인이 해결된 것은 아니다. 정책으로 차단된 경우 IT 담당자의 승인된 배포 절차를 따른다. 보안 경고에 ‘콘텐츠 사용’ 버튼이 없는 경우도 있다. **인터넷 출처 표시가 남은 Excel XLAM은 디지털 서명과 게시자 신뢰만으로 차단을 해결할 수 없다.** [Microsoft: 인터넷 매크로 차단 및 Excel 추가기능 예외](https://learn.microsoft.com/en-us/microsoft-365-apps/security/internet-macros-blocked)

### 3-3. 배포 방식을 구분하기

| 방식 | 권장 적용 | 안내와 한계 |
|---|---|---|
| 검증된 개별 파일 차단 해제 | 소수 사용자·수동 배포 | 해당 파일의 인터넷 출처 표시만 제거. 매크로 정책이나 게시자 신뢰를 자동 변경하지 않음. 업데이트 파일도 재확인 |

신뢰 위치 절차·효과 근거: [Microsoft: 신뢰 위치 설정](https://support.microsoft.com/en-us/office/security-privacy/add-remove-or-change-a-trusted-location-in-microsoft-office), [Microsoft: 신뢰 위치 관리](https://learn.microsoft.com/en-us/microsoft-365-apps/security/trusted-locations). 서명 절차 근거: [Microsoft: VBA 프로젝트 서명](https://support.microsoft.com/en-us/office/vba/digitally-sign-your-vba-macro-project).

보안 센터의 매크로 설정은 조직 정책 또는 알림 포함 차단/서명 정책을 유지하고 위의 좁은 신뢰 경로를 선택한다. ‘모든 매크로 사용’으로 전체 보안을 낮추는 절차를 설명서에 넣지 않는다. ‘VBA 프로젝트 개체 모델에 안전하게 액세스할 수 있음’도 이 코드 실행을 위해 켤 필요가 확인되지 않았다. 위치·서명 설정이 회사 정책으로 잠겨 있으면 사용자가 우회하지 않고 IT 배포를 요청한다.

### F01. 공백 기준 행 삭제

- 버튼/진입: Delete → RowDelete
- 코드 근거: `VBA/Mod_Delete.bas:55`의 `RowDelete`.
- 사용 흐름: 작업 시트를 활성화 → 버튼 → 기준 열의 셀 한 개 선택 → 확인. 선택 구간이 아니라 1행부터 시트 마지막 사용 행까지 검사한다.
- 코드상 결과: 기준 열의 빈 값·일반 공백·수식 결과 빈 문자열에 해당하는 행 전체 삭제. 다른 열의 데이터도 함께 삭제한다.
- 제한·확인 필요: 전체 파일을 별도 저장. 머리글 행도 제외하지 않는다. NBSP 등 모든 공백문자 제거는 확인되지 않았다. 오류값이 있으면 실행 중단과 설정 미복원 가능.

### F02. 행 삭제 후 값 복원

- 버튼/진입: Delete → RowDelete / Restore
- 코드 근거: `VBA/Mod_Delete.bas:25`의 `RestoreBackup`.
- 사용 흐름: RowDelete 실행 직후 같은 통합문서에서 복원 버튼. 다른 통합문서로 전환하지 않는다.
- 코드상 결과: 시트 전체 Cells.Clear 후 백업 UsedRange에 값만 기록. 1회 메모리 백업 소진.
- 제한·확인 필요: 수식·서식·행높이·열너비 등을 원래대로 복구하는 기능이 아니다. 통합문서 식별자 저장이 없어 다른 파일의 같은 이름 시트를 잘못 처리할 수 있다. 재실행하면 백업 덮어쓰기, Excel 종료/VBA 초기화 시 소실.

### F03. 가로 방향 셀 병합

- 버튼/진입: Merge → 셀병합 / 가로
- 코드 근거: `VBA/Mod_Merge.bas:3`의 `셀병합가로`.
- 사용 흐름: 버튼 → 병합할 연속 직사각형 범위 선택 → 확인.
- 코드상 결과: 행별 오른쪽부터 인접 셀의 값이 같거나 오른쪽 셀이 비었을 때 병합, 가운데 정렬.
- 제한·확인 필요: 문자열을 합치는 기능이 아니다. 반복 병합으로 만들어질 최종 병합 범위는 실제 실행 확인 필요. 병합 경고를 숨기므로 복사본에서 확인.

### F04. 세로 방향 셀 병합

- 버튼/진입: Merge → 셀병합 / 세로
- 코드 근거: `VBA/Mod_Merge.bas:58`의 `셀병합세로`.
- 사용 흐름: 버튼 → 병합할 연속 직사각형 범위 선택 → 확인.
- 코드상 결과: 아래쪽부터 인접 셀의 값이 같거나 아래 셀이 비었을 때 병합, 가운데 정렬.
- 제한·확인 필요: 각 열별 처리. 모든 빈칸을 독립적으로 채우는 기능은 아니다. 연쇄 병합은 실행 확인 필요.

### F05. 한글 조사 선택

- 버튼/진입: Korean → 단어 / 조사 연결
- 코드 근거: `VBA/Mod_Korean.bas:43`의 `단어조사연결`.
- 사용 흐름: 결과 셀 한 개 → 기준 단어 셀 한 개 → 조사번호 1 은/는, 2 이/가, 3 을/를, 4 과/와 → 확인.
- 코드상 결과: 결과 셀에 =KoreanParticle(기준셀,번호) 수식. 반환값은 조사만이다.
- 제한·확인 필요: 단어까지 자동 결합하지 않는다. 원문과 합치려면 =A2&KoreanParticle(A2,1). 한글 음절 마지막 글자 기준이며 숫자·영문 발음과 끝 공백은 처리하지 않는다. 빈 문자열 예외 확인 필요. 같은 시트에서 사용.

### F06. 문자열 바이트 수 계산

- 버튼/진입: Korean → 바이트 길이 / (생기부)
- 코드 근거: `VBA/Mod_Korean.bas:117`의 `바이트길이`.
- 사용 흐름: 결과 셀 한 개 → 계산할 문자열 셀 한 개 → 확인.
- 코드상 결과: =CustomLenB(대상셀) 수식. 한글 완성형 음절 3, 나머지 UTF-16 코드 단위 1씩 합산.
- 제한·확인 필요: 일반적인 UTF-8 전체 바이트 계산이나 생기부 공식 산정 규칙 검증은 확인 필요. 한자·이모지·자모 등은 부정확할 수 있다. 줄바꿈 별도 가산 없음. 같은 시트 사용.

### F07. 글 속 계산식 계산

- 버튼/진입: Calc → CalStr
- 코드 근거: `VBA/Mod_Calc.bas:45`의 `CalStr함수`.
- 사용 흐름: 결과 셀 한 개 → 계산할 문자열 셀 한 개 → 확인.
- 코드상 결과: =CalStr(대상셀) 입력. ×→*, ÷→/, 쉼표 제거, 숫자와 + - * / . % ( ) 추출 후 Evaluate. 숫자 사이 제거된 문자 구간에는 곱셈 기호 삽입.
- 제한·확인 필요: 한글 단위의 의미를 해석하지 않는다. 숫자 없으면 0. 오류 수식은 Excel 오류값 가능. 소스·결과는 서로 다른 셀과 같은 시트 사용.

### F08. 수식을 현재 값으로 고정

- 버튼/진입: Calc → 값 변환

- 제한·확인 필요: 원래 수식 소실. 복사본 저장 후 사용. 일반 Ctrl+Z 복구를 보장하지 않는다.

### F12. 빈칸을 위 값으로 이어 새 열 생성

- 버튼/진입: Fill → 오른쪽 채우기
- 코드 근거: `VBA/Mod_Fill.bas:113`의 `오른쪽채우기`.
- 사용 흐름: 버튼 → 기준 열에서 시작 셀 또는 범위 선택 → 확인.
- 코드상 결과: 선택 첫 셀의 열·시작 행부터 해당 열 마지막 비어 있지 않은 행까지 처리. 오른쪽에 열 전체 삽입, 최근 비어 있지 않은 값으로 새 열 채움.
- 제한·확인 필요: 선택 범위 끝 행은 제한으로 쓰지 않는다. 원본은 유지하되 오른쪽 열들이 밀린다. 한 행만 처리하는 경우 vData 차원 불일치로 오류 가능. 끝 공백 행은 포함되지 않음. 자동계산으로 강제 복원.

### F13. 겹치지 않는 무작위 순번

- 제한·확인 필요: 최소·최대 숫자 입력 옵션 없음. 다중 영역·병합 셀 정상 처리 확인 필요. 복사본의 빈 범위 사용.

### F14. 팀원 이름으로 팀명 가져오기

### 설명·정보 및 내부 프로시저

Korean의 ‘설명’은 단어조사연결예시(조사 함수 설명), Calc의 ‘설명’은 CalStr_ex(문자열 계산 설명), About의 ‘정보’는 ShowAbout(제작자·v1.0 (2025)·교무업무 자동화 도구 문구)이다. 별도 데이터 처리 기능으로 세지 않았다. 버전 표시는 코드에 적힌 문자열이며 최신 버전 여부 확인 필요다.

SaveBackup은 RowDelete가 호출하는 내부 값 백업이며 자동 저장 파일 생성이 아니다. RowDelete_ex와 CreateExampleRowDeleteSheet는 Private 예제 시트 생성용 프로시저로 현재 리본 연결이 없다. 예제 그림은 C:\Excel\rowdelete_1.png / rowdelete_2.png 외부 파일에 의존하며 ZIP에는 없다. SeatForm의 btnRun_Click/btnCancel_Click/UserForm_Initialize는 폼 내부 이벤트다.

3. 민: “어떤 도구인지 확인하자.” → About의 ‘정보’ → 코드에 기록된 제작자·버전 문구 확인. 최신 배포본 여부는 작성자에게 확인.

## 8. 배포 전 확인이 필요한 항목

실행 확인 없이 다음을 ‘검증 완료’로 설명하면 안 된다: 모든 기능의 Excel 2024 실행 결과, 셀/시트 보호 상태, 폼 캡션 및 옵션 변경 가능 여부, 연쇄 병합, 비연속 범위, 숫자·영문·빈 문자열 조사, 생기부 공식 바이트 기준, 교차시트 참조, 오답표시 유효성 목록 등록 성공, 단일 행 오른쪽 채우기, 생기부정리 실제 원본 양식.

작성자에게 권장하는 배포 개선은 절대경로 의존을 없앤 XLAM 내장 리본(기존 무인자 Sub를 직접 콜백으로 쓰지 않고 IRibbonControl 인자를 받는 래퍼 등 필요), 값을 넘어선 실제 복구 설계, 파괴적 동작 전 확인, 실패 시 애플리케이션 설정 원복, 오답 판정 목적 재정의, 바이트 규칙 명시, 입력 범위 차원/시트 검사, 검증 후 VBA 서명이다. 이는 **현 파일에 구현된 기능이 아니라 개선 제안**이며 이번 분석에서는 코드를 변경하지 않았다.
